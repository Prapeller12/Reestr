РЕЕСТР ПИСЕМ — СЕТЕВАЯ ВЕРСИЯ ДЛЯ WINDOWS x64

БЫСТРЫЙ ЗАПУСК
1. Полностью распакуйте ZIP в отдельную папку на файловом сервере Windows.
2. Настройте доступ Windows/SMB: пользователям — чтение и выполнение комплекта,
   администратору реестра — изменение подпапки shared (и чтение комплекта).
   Права общего ресурса и NTFS должны разрешать соответствующий доступ.
   Не давайте обычным пользователям запись в shared или изменение EXE/config.
3. Администратор запускает reestr.exe из общей папки на своём компьютере,
   нажимает «Настроить администратора» и задаёт пароль от 10 символов.
   Пароля по умолчанию нет. Сохраните пароль в надёжном месте.
4. Пользователи запускают тот же reestr.exe из этой общей папки либо ярлык на него.
   Вход для просмотра не нужен. Импорт и все изменения — только после входа
   администратора и при наличии права Windows на изменение shared.

Работает по UNC (например \\server\Reestr\reestr.exe) и с сетевого диска.
Серверный сервис, Python, Node.js, Rust и интернет на рабочих местах не нужны.
EXE и встроенный WebView2 копируются на локальный диск при первом запуске.
Подождите, пока окно «Запуск» закончит копирование. Дальше используется кэш.
Клиент требует свободного места в локальном профиле или TEMP (около 1 ГБ).
Windows 10/11 x64 — целевые клиентские ОС. Windows 7/8/8.1 и x86 не поддерживаются.
Фактически проверенные среды этой сборки указаны в отчётах GitHub Actions.

ПЕРЕНОС СТАРЫХ ДАННЫХ
До первой настройки администратора, при закрытой старой программе:
- сделайте резервную копию старой папки;
- скопируйте data\registry.db в shared\initial\registry.db нового комплекта;
- если рядом с registry.db остался непустой registry.db-wal, не переносите
  только DB: откройте и штатно закройте старую программу для завершения записи;
- запускайте новый комплект. Миграция читает копию, исходный файл не изменяет.
После первой публикации используется shared\current.json и shared\snapshots.
Повторное копирование файла в initial НЕ заменяет уже опубликованный реестр.
Не переносите данные между запущенными старой и новой версиями.

РАБОТА
Обычный запуск всегда открывает режим «Только просмотр».
Просмотр, поиск, фильтры, карточки и печать доступны всем.
Администратору доступны импорт, связи, сроки, поля и темы.
«Выйти» сразу отключает изменения. Следующий запуск снова требует входа.
Обновления общей базы проверяются каждые 15 секунд; есть кнопка «Обновить».
При пропадании сети показанные данные сохраняются на экране с сообщением об ошибке;
изменения не считаются сохранёнными до успешной публикации на сервере.
При нескольких администраторах изменения сохраняются последовательно.

В Ганте независимые цепочки в одной стопке раскрываются в отдельные строки.
Внутри каждой строки письма идут по датам, без наложений. Общий ответ/развилка
считаются частью одной связанной цепочки. Есть прокрутка длинных и больших стопок.
Раскрытие доступно также с клавиатуры по фокусу; Escape закрывает стопку.

РЕЗЕРВНЫЕ КОПИИ И ОБНОВЛЕНИЯ
Источник данных — вся папка shared, а не локальный кэш клиента.
Для согласованной резервной копии завершите сеансы администраторов и скопируйте
всю shared. В ней также хранится защищённый хеш пароля администратора.
Снимки не удаляются автоматически: они занимают место после каждой записи.
Очистку старых снимков делайте только при закрытых клиентах, после резервной
копии, сохраняя снимок, указанный в current.json. Не меняйте current.json вручную.
Для восстановления закройте все клиенты и замените всю shared согласованной
резервной копией. При потере пароля используйте резервную копию с известным
паролем; встроенного универсального пароля или скрытого обхода нет.
При обновлении закройте клиенты, распакуйте новый комплект отдельно и перенесите
в него всю shared. Не заменяйте живую shared пустой папкой из ZIP.

ВАЖНО ДЛЯ АДМИНИСТРАТОРА СЕТИ
Это файловая схема SMB, как в согласованном серверном приложении, а не HTTP-сервис.
SQLite никогда не открывается на сетевом диске: клиент читает локальную копию.
Администратор публикует проверенный снимок и атомарно заменяет указатель.
Для защиты от прямой подмены файлов обязательны права Windows/SMB. Пароль
приложения сам по себе не защищает shared от пользователя с правом записи.
Пользователи с доступом на чтение могут копировать реестр; шифрование данных
на диске этим приложением не предоставляется. Ограничьте доступ к общей папке.
Комплект не имеет цифровой подписи издателя; если политика организации требует
подписанные EXE, согласуйте запуск с её ИТ-администратором.
